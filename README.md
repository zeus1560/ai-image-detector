# CLAUDE.md — AI 생성 이미지 판별 서비스

이 파일은 이 레포에서 작업하는 AI(Claude Code, Claude 프로젝트)가 먼저 읽는 프로젝트 기준 문서다. 여기 적힌 규칙이 다른 지시와 충돌하면 사람에게 먼저 확인한다.

## 프로젝트 한 줄 요약

카톡·인스타로 전송되며 압축된 사진에서도 AI 생성 여부를 판별하는 서비스. 강남대학교 컴퓨터비전 수업 조별 미니 프로젝트 (14주차 최종 발표).

핵심 결과 문장: "압축하면 기존 판별 모델 성능이 X% 떨어지고, 우리 방법으로 Y%까지 회복한다."

## 팀과 담당

| 이름 | 담당 | 내 폴더 | 작업 도구 |
| --- | --- | --- | --- |

## 협업 규칙 (폴더 주인 방식)

- 브랜치를 나누지 않고 모두 main에서 작업한다. 대신 **각자 자기 폴더만 수정한다.** 폴더가 겹치지 않으니 충돌이 나지 않는다.
- 상대 폴더의 파일을 고쳐야 하면 직접 수정하지 않고 먼저 알린다.
- 공용 파일(`CLAUDE.md`, `DECISIONS.md`, `docs/spec/data-contract.md`)은 합의 후 수정하고, 수정하면 `DECISIONS.md`에 한 줄 남긴다.
- 이상진은 노트북을 GitHub 웹의 "Add file → Upload files"로 `notebooks/`에 올린다. 어려우면 Google Drive 공유 폴더에 두고 안승주가 올린다.

## 작업 방식

- 한국어로 답변한다. 한 단계씩 진행하고 왜 그렇게 하는지 이유를 함께 설명한다.
- 모델 코드는 `src/model/`에 .py 파일로 작성하고, 작은 샘플로 로컬 CPU에서 먼저 돌려본다.
- 실제 학습은 `notebooks/run_model.ipynb`에서 한다. 이 노트북은 Colab 서버에서 실행되므로 내 컴퓨터 파일을 직접 읽지 못한다. 첫 칸에서 GitHub 레포를 받아오고(`git clone` 또는 `git pull`) Google Drive를 연결한 뒤 `src/model/` 코드를 불러 실행한다.
- 흐름: VS Code에서 코드 수정 → GitHub에 push → 실행 노트북에서 pull 후 실행 → 결과를 실험 기록에 정리.
- 데이터와 모델 가중치는 Google Drive에 저장하고 GitHub에는 올리지 않는다.
- 무료 Colab은 GPU가 거절되거나 세션이 끊길 수 있다. 학습 중간 결과(체크포인트)를 Drive에 저장한다.

## 스펙 주도 개발 (모델 코드)

안승주의 모델 코드는 스펙 주도로 개발한다. 데이터 작업(이상진)은 데이터 계약만 지키면 되고 이 절차를 강제하지 않는다.

1. **스펙 먼저.** `docs/spec/_template.md`를 복사해 `SPEC-번호-이름.md`를 쓴다. 상태는 "초안"으로 시작한다.
2. **확정된 스펙만 구현한다.** 안승주가 검토하고 상태를 "확정"으로 바꾸기 전에는 코드를 쓰지 않는다. AI는 스펙 초안 작성과 질문까지만 하고, 확정은 사람이 한다.
3. **스펙대로 구현한다.** 스펙에 없는 기능을 임의로 추가하지 않는다. 필요해 보이면 제안만 한다.
4. **완료 기준으로 검증한다.** 구현 후 완료 기준을 하나씩 실제로 확인하고, 확인한 항목만 체크한다. 실행하지 않은 항목은 체크하지 않는다.
5. **스펙과 다르게 가야 하면 스펙부터 고친다.** 코드를 먼저 바꾸지 않고, 스펙 수정을 제안해 확인받은 뒤 구현한다.
6. 다 끝나면 상태를 "구현 완료"로 바꾸고, 실험이면 `docs/experiments/`에 결과를 기록한다.

예정된 스펙 (순서대로):
- SPEC-01 manifest 데이터 로더 (CIFAKE를 데이터 계약 형식으로 감싸기, split 겹침 검사)
- SPEC-02 베이스라인 학습
- SPEC-03 조건별 평가 (정확도, 실제 사진 오탐률, 생성 이미지 미탐률)
- SPEC-04 압축 증강 재학습
- SPEC-05 Grad-CAM 시각화
- SPEC-06 Gradio 데모 (공동)

## 반드시 지킬 규칙

1. **결과 수치는 실제 실행 로그에서만 가져온다.** 실행하지 않은 정확도, 오탐률 등을 추정하거나 지어내지 않는다. 확인되지 않은 수치는 `(미확인)`으로 표시한다.
2. **데이터 누수 금지.** 같은 `origin_id`의 원본과 변형본은 모두 같은 split(train/val/test)에 있어야 한다. 학습 전에 자동 검사를 돌리고, 겹치면 학습을 멈춘다.
3. **포맷 편향 금지.** 실제/생성 이미지는 같은 포맷, 크기, 색상 모드, 같은 압축 조건으로 맞춘 뒤 학습한다.
4. **재현성.** 모든 실험은 seed를 고정하고 설정값을 기록한다.
5. **테스트셋은 학습·튜닝에 쓰지 않는다.** 하이퍼파라미터 조정은 val로만 한다.
6. **실험이 끝나면 `docs/experiments/`에 기록한다.** 기록 없는 결과는 발표에 쓰지 않는다.

## 평가 지표

- 정확도
- 실제 사진 오탐률: 실제 사진을 AI 생성으로 잘못 판정한 비율 (서비스에선 이게 가장 치명적)
- 생성 이미지 미탐률: AI 생성 이미지를 실제로 판정한 비율
- 조건별로 따로 보고: 원본 / 코드 압축(품질별) / 실제 카톡 전송본 / 최신 생성 모델

## 데이터셋 역할

| 데이터셋 | 역할 |
| --- | --- |
| CIFAKE (32×32) | 코드·파이프라인 검증용. 압축 실험에는 쓰지 않는다 |
| GenImage 하위 세트 (고해상도) | 본 실험: 압축 실험, 교차 생성기 일반화 |
| 자체 압축 데이터 | 핵심 문제 증명: 압축 조건별 성능 비교 |
| 실제 카톡 전송본 | 코드 압축이 실제와 같은지 검증 (테스트 전용) |
| 최신 모델 테스트셋 (50~100장) | 학습에 없던 생성 모델에 대한 한계 확인 (테스트 전용) |

데이터셋 링크와 참조 코드 목록은 `README.md`에 있다.
